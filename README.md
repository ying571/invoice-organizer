# 发票整理工具（Windows 便携版）

这是一个离线运行的采购凭证整理工具。它会识别发票 PDF 与交易截图中的金额、日期、订单号和商品信息，按可确认的关系配对，并为每笔采购生成一个资料包。

资料包包含一份重命名后的发票 PDF 和一份只嵌入凭证截图的 Word 文档，适合后续人工复核、归档或报销使用。

## 运行环境

- 支持 64 位 Windows 10 / 11。
- 无需安装 Python、Microsoft Office 或 LibreOffice。
- 无需联网；OCR 与运行所需组件均已内置。
- 请保留 `runtime` 文件夹及其全部内容，并将它与 `双击整理发票.cmd` 放在同一目录。

## 使用方法

1. 解压整个工具文件夹；不要只复制 `双击整理发票.cmd`。
2. 将本次要处理的发票 PDF 和截图直接放到工具根目录（即 CMD 文件所在目录）。程序不会递归读取子文件夹。
3. 双击 `双击整理发票.cmd`。
4. 等待命令窗口提示完成或存在待确认项，再打开新生成的 `整理结果` 目录查看。

每次运行都会创建新的结果目录。如果 `整理结果` 已存在，后续结果会依次命名为 `整理结果_2`、`整理结果_3` 等，已有结果不会被覆盖。

## 可识别的材料

### 必需材料

- 发票：根目录中的 PDF 文件。程序仅将 PDF 视为发票并读取第一页。
- 凭证截图：每笔至少需要一张可识别的商品订单截图、支付截图或微信转账截图。

### 支持的截图格式

`JPG`、`JPEG`、`PNG`、`BMP`、`WEBP`、`TIF`、`TIFF`（不区分扩展名大小写）。

### 截图类型

程序会根据 OCR 文字将截图区分为：

- 商品订单截图：通常含“订单信息”“实付款”“交易成功”等内容。
- 支付截图：通常含“账单详情”“支付成功”“付款方式”等内容。
- 微信转账截图：通常含“已收款”“转账时间”“转账给”等内容。

无法判断类型的截图不会用于生成资料包，并会写入待确认清单。

## 配对规则

程序优先按金额进行配对；同金额候选不止一个时，会继续尝试订单号和商品名称信息以缩小范围。金额、订单号或商品信息无法让关系唯一确定时，材料不会被强行配对，而会保留给人工复核。

同一张发票可匹配商品订单截图和支付截图各一张；若两者均缺失，则可使用一张微信转账截图。已被成功使用的截图不会再次分配给其他发票。

对于 OCR 已识别字段完全相同的重复发票或截图，程序会随机选取其中一份参与配对，将整组文件复制到 `重复文件` 目录，并在日志中记录所选文件与全部重复文件路径。未被选中的重复材料会保留在原位置，不会作为未配对材料重复报出。

## 输出内容

每个可确认的资料包均为以下结构：

```text
整理结果/
└─ 金额 商品简称 YYYY.MM.DD/
   ├─ 金额 商品简称 YYYY.MM.DD.pdf
   └─ 金额 商品简称 YYYY.MM.DD.docx
```

其中：

- 金额取发票识别出的金额，保留两位小数。
- 商品简称优先取商品订单截图中的商品标题；支付截图仅在商品订单截图未提供名称时作为弱兜底。仅有转账截图时，名称取发票项目名称；上述均不可用时，才使用发票项目名称兜底。
- 程序会清理标题中的价格、数量、部分规格和不适合文件名的字符，并对少数常见商品名称进行归一化。
- 日期优先取发票开票日期；发票日期未识别时，依次取商品订单截图、支付截图、转账截图中的时间。
- PDF 为原发票的副本，文件内容不会被修改。

Word 文档采用 A4 纵向、四边 1 cm 页边距，不写标题、说明或表格，仅嵌入凭证图片：

- 同时匹配商品订单截图和支付截图时，共两页：第 1 页商品订单截图，第 2 页支付截图。
- 只匹配到商品订单截图、支付截图或微信转账截图时，仅生成一页。
- 图片会按页面宽度和最大 23 cm 高度等比缩放。

## 复核文件与日志

结果目录还可能包含以下内容：

| 文件或目录 | 用途 |
| --- | --- |
| `运行日志.txt` | 带耗时的处理进度、配对结果和重复材料汇总。订单号仅记录末四位。 |
| `识别日志.json` | 每个文件的识别结果、命名来源、配对方式和输出名称，适合进一步排查。 |
| `待确认.txt` | 未识别字段、无法配对、无法判断截图类型或 Word 校验失败等需要人工处理的问题。仅在存在问题时生成。 |
| `未配对材料` | 待确认的发票或截图副本，方便集中查看；原文件仍保留在根目录。 |
| `重复文件` | OCR 字段完全相同的重复材料副本。 |

程序会在正常结束前删除用于发票 OCR 的临时识别缓存。若发生未捕获的运行错误，会在工具根目录写入 `发票整理错误日志.txt` 以便排查。

## 原件与隐私

- 原始 PDF 和截图只会被读取或复制，不会被移动、改名或删除。
- 程序不会上传或联网传输材料。
- 运行日志和识别日志中的订单号会脱敏为仅保留末四位；请仍按内部资料要求妥善保管结果目录。

## 常见情况

### 没有生成资料包

请查看 `待确认.txt`。常见原因包括：根目录没有 PDF、截图类型无法识别、金额未识别、没有可用截图、同金额材料无法唯一确认，或商品名称/日期无法获取。

### 命令窗口显示“部分材料未能配对”

这表示程序已完成运行，但仍有待确认项。请查看结果目录中的 `待确认.txt`、`未配对材料` 和 `识别日志.json`；补齐或替换材料后，可将需要重试的原始文件放回根目录再次运行。

### 为什么有“重复文件”目录

当两份或以上材料的可识别字段完全相同时，程序无法判断哪一份才应使用，会随机选一份完成本次配对，并保留整组副本供人工确认。若需固定选用某个文件，请先在根目录中只保留需要的那一份后重新运行。
